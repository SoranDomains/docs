title: "HTTP API overview"
description: "Distinguish strict chain-backed payment reads from indexed discovery and optional services."
---

The HTTP API combines strict current contract reads with indexed discovery, history and hosted services. The source of truth remains the chain; an HTTP response still requires trusting the serving API and its RPC.

The public testnet API at `https://api.soran.domains` serves the fresh setup in [release status](/reference/release-status). `https://resolve.soran.domains` is a resolution alias. Match the API to the contracts and network you integrate.

## Choose the right source

| Need | Endpoint or method |
| --- | --- |
| Complete address and optional memo | `/v1/payment/{namespace}/{label}` or on-chain `resolve_payment` |
| Memo-free address convenience | `/v1/resolve/{namespace}/{label}`; required memo returns an error |
| Current payment plus selected records | `/v1/records/{namespace}/{label}` |
| Contract source of truth without Soran HTTP | [Universal Lookup ABI](/api/onchain-resolution) |
| Indexed ownership candidates | `/v1/names/by-holder/{address}` |
| Verified account Primary | `/v1/primary/{address}` |
| Namespace discovery | `/v1/namespaces` and optional directory |
| History, raw events and gaps | [Explorer API](/api/events) |
| Namespace fee policy/receipt/credit | [Claim fee API](/api/claim-fees) |

The new payment routes use configured Universal Lookup with anchor/version checks and no fallback on failure. Compatibility deployments can explicitly operate a native direct path; verify which setup you are integrating. Indexed holders, cold records and cached Registrar addresses are never substitutes for a failed current payment read.

## Conventions

- Public `/v1` routes need no API key. Some optional marketplace routes create intents rather than merely reading data.
- Responses are JSON; errors have a machine-readable `error` field.
- Full-name payment inputs reject non-ASCII before lowercasing ASCII uppercase. Names are not Unicode-normalized.
- Large integer token amounts and generations use decimal strings where JSON cannot preserve their contract precision.
- Rate limits apply and may differ by deployment; handle `429`.
- Payment, records, Primary and claim-fee reads use `Cache-Control: no-store`. Recheck instructions before signing or paying.

## Discovery and freshness

`/v1/namespaces`, holdings, directory and history endpoints use bounded pages with opaque cursors. Follow `nextCursor` and inspect `hasMore`, `truncated` and coverage. `/v1/lookup?q=...` is bounded search with truncation signals; `/v1/showcase` is a curated active-namespace grid, not exhaustive discovery.

`/v1/stats` gives indexed counts. `/v1/ledger/head` gives the observed head. Neither is proof of complete, fresh indexing; inspect `/v1/coverage` and [status](/api/status).

`GET /health` is a process-liveness endpoint. Use `/v1/status` for component measurements. Authenticated console management routes are outside this public reference except the tenant-facing paid-claim preparation contract described in the claim fee guide.
