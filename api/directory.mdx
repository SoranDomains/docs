title: "Directory and namespace discovery"
description: "Bounded indexed discovery, billing filters and explicit continuation."
---

The directory is a hosted discovery feature. It suggests names held by an address and namespace candidates; it does not prove current ownership, reverse identity or payment instructions.

```http
GET /v1/directory/reverse/{address}?limit=20
GET /v1/directory/namespaces?limit=100
GET /v1/namespaces?limit=100
```

The reverse directory accepts G and C addresses and defaults to 20 entries. Limits are 1–100. Namespace pages default to 100. Continue with the returned `nextCursor`; cursors are opaque and scoped to the endpoint/filter. Responses expose `hasMore`, `truncated` and coverage.

Reverse entries contain `name`, `namespace` and `namespaceDisplay`. Namespace directory entries contain label and hosted presentation metadata, such as display name and logo. Treat uploaded presentation values as untrusted content.

## Billing filter

When billing enforcement is enabled on a deployment, directory discovery may include only namespaces with an active subscription. The response's `filtered` boolean describes that policy filter.

`filtered: false` means no subscription filter was applied. It **does not** mean all namespaces fit on the current page, all history was indexed or the result cannot omit anything. Follow continuation and inspect coverage either way.

Directory presence does not gate on-chain forward reads. If you know a name, resolve it directly rather than requiring that it appear in a hosted directory. Hosted service expiry does not revoke the namespace.

For holder verification use [holdings pages](/api/resolution#holdings-pages) and current name metadata. For account display identity use on-chain reverse/Primary, not holder membership.
