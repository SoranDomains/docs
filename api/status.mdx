## Status

```http
GET /v1/status
```

The endpoint checks database access, reports the API's last observed RPC ledger and compares stored indexer progress with that cached head. The example below illustrates its shape; it is not the current service status.

```json
{
  "ledger": 55123001,
  "components": [
    { "name": "Database", "state": "operational" },
    { "name": "Stellar RPC", "state": "operational" },
    {
      "name": "Indexer",
      "state": "operational",
      "ledger": 55122999,
      "lag": 2,
      "processedAt": "2026-08-24T10:15:04.000Z",
      "deadLetters": 0
    }
  ]
}
```

### Component semantics

- **Database** — `operational` or `down`.
- **Stellar RPC** — `operational` when the API has a nonzero cached ledger observation, `down` before one is available. Failed refreshes retain the last successful value, so this flag alone does not prove current RPC reachability or a fresh head.
- **Indexer** — `lag` compares its processed ledger with the API's cached head, clamped to zero; `processedAt` is when it last wrote progress. It is `operational` when it has progress less than 120 seconds old and the known lag is below 200 ledgers. `deadLetters` counts unresolved indexing failures separately. An operational state does not establish complete history; inspect `/v1/coverage`, its freshness and explicit gaps.

### Extra components, when enabled

Deployments with billing or the marketplace enabled report their payment watchers with the same discipline — a stalled watcher must look stalled, never like "no payments today":

```json
{ "name": "Billing watcher", "state": "operational", "cursorAgeSeconds": 12, "quarantined": 0 }
```

```json
{ "name": "Escrow watcher", "state": "operational", "cursorAgeSeconds": 9, "parkedPayouts": 0 }
```

- `cursorAgeSeconds` — time since the watcher last completed a poll (it heartbeats even on empty polls); a growing age means the watcher is `lagging` or dead, and a watcher that has never run reports `unknown` rather than `operational`.
- `quarantined` — billing payments needing operator action (e.g. refunds).
- `parkedPayouts` — escrow payouts that could not be paid out. Any parked payout marks the escrow watcher `degraded` regardless of freshness.

States you may see across components: `operational`, `lagging`, `degraded`, `down`, `unknown`.

## Allocation queue

```http
GET /v1/allocations
```

The public queue behind [namespace claiming](/concepts/claiming-a-namespace) groups recent claims in the announced, objected and awarded states. It includes an **estimated countdown** based on indexed announcement/window data and the server's clock. The queue is drawn from the most recent 200 claims; withdrawn and rejected claims are not shown.

```json
{
  "ledger": 55123001,
  "pending": [
    {
      "id": "alloc_…",
      "namespace": "acme",
      "claimant": "Acme Corp",
      "claimantAccount": "GACME…",
      "state": "announced",
      "basis": ["trademark"],
      "claimantResponse": null,
      "evidence": [{ "label": "USPTO filing", "url": "https://…" }],
      "announcedLedger": 55100000,
      "deadline": "2026-08-27T09:00:00.000Z",
      "remainingSeconds": 259140,
      "elapsed": false,
      "awardedAt": null,
      "objections": []
    }
  ],
  "objected": [],
  "awarded": []
}
```

- `pending` / `objected` / `awarded` — claims in the announced window, claims under an active objection, and completed awards.
- `basis` — an **array** of the claim's asserted basis kinds (e.g. `["trademark", "dns", "first_use"]`); `evidence` — an **array of labeled links**, each a `{ "label", "url" }` object.
- `deadline`, `remainingSeconds`, `elapsed` — an estimated claim-window countdown computed at response time. `remainingSeconds` is rounded to the nearest second. `elapsed: true` does not establish on-chain readiness: the contract uses ledger time and checks the claim's current state.
- `objections` — **live** objections only (dismissed or timed-out objections are resolved on chain and don't display as active disputes). Each carries the objector's name, the basis, and the objection bond in XLM:

```json
{ "objector": "Other Corp", "basis": "prior-use", "bondXlm": "100.0000000" }
```

Poll this endpoint to build claim-tracking UIs. Its `ledger` is a cached observed head, not proof every displayed claim was processed through that ledger. Check indexer status and coverage; confirm claim and fee state on chain before signing.

The queue is not a fee receipt or complete settlement archive. Use the [claim fee API](/api/claim-fees) for escrow policy, outcome and recoverable credit. The fresh deployment uses 5,000 testnet XLM for public namespace claims; objection bonds are separate. Removing Lookup upgrade delay does not remove the claim window.

See [release status](/reference/release-status) for which setup is deployed.
