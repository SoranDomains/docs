---
title: "Universal Lookup contract"
description: "A shared on-chain ABI for wallets, explorers and other contracts across all namespaces."
---

Read **Universal Lookup** for the authoritative contract result. It follows current Registry routing and invokes each namespace's supported contracts. You do not need a Soran SDK or Soran HTTP API to use it.

<Note>
Use verified IDs for one network from [release status](/reference/release-status). Predicted vanity IDs and older deployment pins are not interchangeable. The examples below target Stellar SDK 17 and the new Lookup ABI.
</Note>

The constructor is `(registry: Address, governance: Address, legacy: Option<LegacyCodeHashes>, primary: Option<Address>)`. `LegacyCodeHashes` contains exact Registrar and Resolver Wasm hashes. The optional Primary must be an active Wasm contract with the same Registry anchor. These anchors are fixed by the current implementation; governed code replacement remains possible.

## Forward result

`resolve(name:String) -> Resolution` takes a canonical lowercase name and returns:

```text
Resolution {
  name: String,
  registrar: Address,
  resolver: Option<Address>,
  generation: u64,
  result: NativePayment(Payment) | LegacyAddress(Address)
}
Payment { address: Address, memo: PaymentMemo }
PaymentMemo = None | Id(u64) | Text(String) | Hash(BytesN<32>)
```

`NativePayment` is a complete instruction. `LegacyAddress` explicitly leaves memo capability unknown. Strict `resolve_payment(name) -> Payment` rejects legacy results; `resolve_address(name) -> Address` additionally rejects a native required memo.

Canonical names contain exactly two 1–63-byte labels of lowercase ASCII letters/digits/interior hyphens. Memos permit None, unsigned 64-bit ID, 1–28 UTF-8 byte text or 32-byte hash. Contract destinations support None only. See [payment behavior](/sdk/resolving-names).

## Other read methods

| Method | Result |
| --- | --- |
| `registry()` | Configured Registry Address |
| `version()` | Numeric ABI version `1` |
| `primary()` | Optional configured Primary Address |
| `namespace_metadata(namespace:String)` | Optional NamespaceMetadata |
| `name_metadata(name:String)` | Optional NameMetadata |
| `text(name:String,key:Symbol)` | Optional String |
| `reverse(namespace:String,address:Address)` | Optional canonical account display name |
| `primary_name(address:Address)` | Optional canonical Primary name |

```text
NamespaceMetadata {
  namespace: String, node: BytesN<32>, owner: Address,
  registrar: Option<Address>, resolver: Option<Address>,
  resolver_locked: bool, resolver_attested: bool,
  registrar_tainted: bool, resolver_tainted: bool, permanent: bool,
  policy: Option<NamespacePolicy>
}
NamespacePolicy {
  reclaimable: bool, transferable: bool, tradeable: bool,
  default_term_secs: u64, trade_fee_bps: u32
}
NameMetadata {
  name: String, node: BytesN<32>, registrar: Address,
  holder: Address, builtin_address: Address, generation: u64,
  expires_at: u64, active: bool, no_expiry: bool,
  namespace_permanent: bool
}
```

Metadata is not a payment fallback. `builtin_address` can differ from effective Resolver instructions. Finite expiry occurs when ledger time is strictly greater than `expires_at`; zero means no ownership deadline. A name's metadata can remain available with `active=false` after expiry.

`text` accepts a nonempty Symbol of at most 32 bytes and returns at most 4,096 UTF-8 bytes; larger historical values return `ReadTooLarge`. The raw `payment` text key is not a replacement for typed payment reads.

Reverse and Primary results receive a current forward check, including required memos as valid account routes. Their underlying contracts may collapse absent/stale/failed proof into None; a returned None does not diagnose every downstream failure. See [identity limits](/sdk/reverse-and-primary).

## Read through Soroban RPC

This example makes one unsigned read simulation. `lookupId`, `registryId`, `rpcUrl` and `passphrase` come from verified deployment configuration.

```ts
import {
  Account, Contract, TransactionBuilder, rpc, nativeToScVal, scValToNative,
} from "@stellar/stellar-sdk";

async function view(contractId: string, fn: string, args: ReturnType<typeof nativeToScVal>[] = []) {
  const server = new rpc.Server(deployment.rpcUrl);
  const tx = new TransactionBuilder(
    new Account("GAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAWHF", "0"),
    { fee: "100", networkPassphrase: deployment.passphrase },
  ).addOperation(new Contract(contractId).call(fn, ...args)).setTimeout(30).build();
  const sim = await server.simulateTransaction(tx, undefined, undefined, false);
  if (rpc.Api.isSimulationRestore(sim)) throw new Error("Contract state needs restoration");
  if (!rpc.Api.isSimulationSuccess(sim) || !sim.result) throw new Error("Read failed");
  return scValToNative(sim.result.retval);
}

if (await view(deployment.lookupId, "registry") !== deployment.registryId) {
  throw new Error("Wrong Registry anchor");
}
if (await view(deployment.lookupId, "version") !== 1) throw new Error("Unsupported ABI");
const raw = await view(deployment.lookupId, "resolve_payment", [
  nativeToScVal("alice.nova", { type: "string" }),
]);
// Strictly decode raw against Payment before use; never drop or coerce its memo.
```

Restore detection must precede the success check. Anchor/version reads are compatibility checks, not a code hash pin. Each `view` call can run at a different ledger; one `resolve_payment` invocation obtains its dependent answer within one simulation snapshot.

Soroban `contracttype` structs encode as field-symbol maps. Enum variants encode as vectors such as `[None]`, `[Id, u64]` or `[NativePayment, Payment]`; symbols are not strings in XDR. Preserve u64 precision as bigint or decimal strings. Validate shape, variant arity, addresses and memo bounds after decoding. The [SDK](/sdk/reference) supplies strict decoders if you choose to use it.

Dependency failure never means a memo-free result. Unsupported methods on an older Lookup must not trigger a silent direct-read fallback.

## Raw state and discovery

Raw ledger entries are useful for indexing but bypass contract validation. Separate reads can mix generations or routing, and missing live entries may be archived rather than unowned. Use typed contract methods for payment answers and [versioned events](/api/events) for discovery. Historical data can be displayed as history, not silently promoted to a current destination.

Lookup stores configuration, including fixed Registry and optional Primary anchors in this implementation. It does not maintain copied names or memos. [Governance](/concepts/governance) can change its executable code without a mandatory delay.
