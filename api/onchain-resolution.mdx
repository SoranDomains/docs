## On-chain resolution

Read **Universal Lookup** for the authoritative contract result. It follows current Registry routing and invokes each namespace's supported contracts. You do not need a Soran SDK or Soran HTTP API to use it.

<Note>
The addresses below are the native-muxed **5 September 2026 testnet deployment, verified at 18:10 UTC**. Its Resolver and Lookup use ABI 2; Registry retains namespace-and-role-bound salt version 1. Use the IDs together; the earlier deployments remain separate. The examples target Stellar SDK 17 and Lookup ABI version 2.
</Note>

Wallets and explorers call **Universal Lookup**. It discovers the current Registrar and Resolver for the requested namespace through the Registry. Namespace-specific contracts, including the [Nova example contracts](/reference/release-status#nova-namespace-contracts), belong in a deployment reference rather than an integration's global address list.

The constructor is `(registry: Address, governance: Address, legacy: Option<LegacyCodeHashes>, primary: Option<Address>)`. `LegacyCodeHashes` contains exact Registrar and Resolver Wasm hashes. The optional Primary must be an active Wasm contract with the same Registry anchor. These anchors are fixed by the current implementation; governed code replacement remains possible.

## Forward result

`resolve_v2(name:String) -> ResolutionV2` takes a canonical lowercase name and returns:

```text
ResolutionV2 {
  name: String,
  registrar: Address,
  resolver: Option<Address>,
  generation: u64,
  result: NativePayment(PaymentDestination) | LegacyAddress(Address)
}
PaymentDestination = Direct(Payment) | Muxed(MuxedPayment)
Payment { address: Address, memo: PaymentMemo }
PaymentMemo = None | Id(u64) | Text(String) | Hash(BytesN<32>)
MuxedPayment { account: Address, id: u64 }
```

`Direct` contains a G account with an optional transaction memo, or a C contract with `None`. `Muxed` contains a G account and its exact unsigned 64-bit muxed ID. These two fields completely define the standard M address; an integrator can encode it without a Soran SDK or database. A muxed ID is not a transaction memo.

`NativePayment` is a complete instruction. `LegacyAddress` explicitly leaves memo capability unknown. Strict `resolve_destination(name) -> PaymentDestination` rejects legacy results.

The original `resolve(name) -> Resolution` and `resolve_payment(name) -> Payment` retain their V1 shapes for direct G/C instructions but reject muxed records with `MuxedDestination`. `resolve_address(name) -> Address` also rejects required memos. Never use a rejected old read as permission to substitute the base G address.

Canonical names contain exactly two 1–63-byte labels of lowercase ASCII letters/digits/interior hyphens. Classic G destinations permit None, unsigned 64-bit ID, 1–28 UTF-8 byte text or 32-byte hash. Contract C destinations support None only. Muxed destinations require a G base and a u64 ID, with no separate memo in this ABI. See [address types and complete examples](/concepts/payment-destinations).

The native Resolver exposes `payment_version() == 2`, `destination_version() == 2`, `resolve_destination(name)` and holder-authorized `set_muxed(name,holder,account,id)`. Its existing `set_payment` method remains the atomic G/C-and-memo writer. The muxed base, ID, address record and configuration marker are updated in one transaction and bound to the current ownership generation.

Lookup supports a successful native Resolver version `1` using its V1 payment method, and version `2` using its V2 method after checking `destination_version() == 2`. Unknown versions, failed capability reads and failed V2 results are errors; they never trigger a V1 fallback.

```text
NamespaceMetadata {

  registrar: Option<Address>, resolver: Option<Address>,

  registrar_tainted: bool, resolver_tainted: bool, permanent: bool,

  default_term_secs: u64, trade_fee_bps: u32
}
NameMetadata {
  name: String, node: BytesN<32>, registrar: Address,
  holder: Address, builtin_address: Address, generation: u64,
  expires_at: u64, active: bool, no_expiry: bool,
  namespace_permanent: bool

```

Metadata is not a payment fallback. `builtin_address` can differ from effective Resolver instructions. Finite expiry occurs when ledger time is strictly greater than `expires_at`; zero means no ownership deadline. A name's metadata can remain available with `active=false` after expiry.

`text` accepts a nonempty Symbol of at most 32 bytes and returns at most 4,096 UTF-8 bytes; larger historical values return `ReadTooLarge`. The raw `payment` text key is not a replacement for typed payment reads.

Reverse and Primary results receive a current forward check, including required memos as valid account routes. Muxed payment destinations do not become base-account identity proofs; a muxed forward answer is rejected. Their underlying contracts may collapse absent/stale/failed proof into None; a returned None does not diagnose every downstream failure. See [identity limits](/sdk/reverse-and-primary).

## Read through Soroban RPC

Each `view` call makes an unsigned read simulation. This example pins the deployed testnet configuration, checks the Lookup anchor and ABI, then requests the address and optional memo together. Replace `alice.nova` with an active, issued name; example names are not promised to exist.

```ts
import {
  Account, Contract, TransactionBuilder, rpc, nativeToScVal, scValToNative,
} from "@stellar/stellar-sdk";

const deployment = {
  lookupId: "CDSORANKG77YZITKWCLWGPKLB2R3HPTP4D6KKZZ7X3R5HLXLMNOTGCDD",
  registryId: "CASORANI5CN2NJFEO2MGTRDA35AOEF3D3OCVBWN3FS6B6FXNQ74RTJ7H",
  rpcUrl: "https://soroban-testnet.stellar.org",
  passphrase: "Test SDF Network ; September 2015",
};

async function view(contractId: string, fn: string, args: ReturnType<typeof nativeToScVal>[] = []) {
  const server = new rpc.Server(deployment.rpcUrl);
  const tx = new TransactionBuilder(
    new Account("GAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAWHF", "0"),
    { fee: "100", networkPassphrase: deployment.passphrase },
  ).addOperation(new Contract(contractId).call(fn, ...args)).setTimeout(30).build();
  const sim = await server.simulateTransaction(tx, undefined, undefined, false);
  if (rpc.Api.isSimulationRestore(sim)) throw new Error("Contract state needs restoration");
  if (!rpc.Api.isSimulationSuccess(sim) || !sim.result) throw new Error("Read failed");
  return scValToNative(sim.result.retval);
}

if (await view(deployment.lookupId, "registry") !== deployment.registryId) {
  throw new Error("Wrong Registry anchor");
}
if (await view(deployment.lookupId, "version") !== 2) throw new Error("Unsupported ABI");
if (await view(deployment.lookupId, "destination_version") !== 2) throw new Error("Unsupported destination ABI");
const raw = await view(deployment.lookupId, "resolve_destination", [
  nativeToScVal("alice.nova", { type: "string" }),
]);
// Strictly decode Direct(Payment) or Muxed({ account, id }) before use.
// Preserve the memo or muxed ID exactly; never collapse Muxed to an account-only answer.
```

Restore detection must precede the success check. Anchor/version reads are compatibility checks, not a code hash pin. Each `view` call can run at a different ledger; one `resolve_destination` invocation obtains its dependent answer within one simulation snapshot.

Soroban `contracttype` structs encode as field-symbol maps. Enum variants encode as vectors such as `[None]`, `[Id, u64]` or `[Direct, Payment]`, `[Muxed, { account, id }]` or `[NativePayment, PaymentDestination]`; symbols are not strings in XDR. Preserve u64 precision as bigint or decimal strings. Validate shape, variant arity, addresses and memo bounds after decoding. The [SDK](/sdk/reference) supplies strict decoders if you choose to use it.

## Raw state and discovery

Raw ledger entries are useful for indexing but bypass contract validation. Separate reads can mix generations or routing, and missing live entries may be archived rather than unowned. Use typed contract methods for payment answers and [versioned events](/api/events) for discovery. Historical data can be displayed as history, not silently promoted to a current destination.

Lookup stores configuration, including fixed Registry and optional Primary anchors in this implementation. It does not maintain copied names or memos. [Governance](/concepts/governance) can change its executable code without a mandatory delay.
