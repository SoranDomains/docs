Soran is available on **Stellar testnet**. Mainnet is not available yet. This page was reviewed on **8 September 2026**.

<span id="verified-claim-behavior" />

The current setup supports automatic username claims, G accounts with or without a memo, muxed M addresses and C contract destinations. Reverse and Primary lookup support the complete M address, including its routing ID.

For a working integration, start with the [quickstart](/quickstart) or try the [live examples](/live-examples).

## Network, versions and fees

| Setting | Value |
| --- | --- |
| Network | Stellar testnet |
| RPC | `https://soroban-testnet.stellar.org` |
| Network passphrase | `Test SDF Network ; September 2015` |
| Public namespace application | **5,000 XLM** upfront |
| Username claim | Free or a flat XLM price set by the namespace owner |

The namespace application fee goes into Allocator escrow. Award pays the configured recipient; rejection or stuck cancellation refunds 100%; withdrawal or expiry refunds 80%. See [namespace claim outcomes](/concepts/claiming-a-namespace).

A username fee goes directly to the owner's configured treasury when the claim succeeds. There is no username approval escrow or mandatory annual Soran ownership fee. Transaction and storage costs are separate. Read the namespace's current quote before showing a price; see [automatic claiming](/owner/automatic-claiming).

## Allocator upgrade

The Allocator records [case-specific rulings and explanations](/reference/namespace-objections) on chain. Code-upgrade execution and cancellation bind the exact reviewed code hash. Reopening cancellation and execution now bind the [exact proposal identity](/reference/namespace-objections#reopening-proposals), so a replacement proposal needs a new review. The [latest confirmed 8 September upgrade](https://stellar.expert/explorer/testnet/tx/a9c77709a1a4e51fa4a5ca74647e332302f629ef53578bb3bc912fd7e29ca9c3) keeps the same contract address and storage schema `4`.

Earlier upgrades that day added case-specific rulings, removed the mandatory wait for new governance-approved code proposals and fixed XLM settlement to G accounts that do not yet exist. A payout can create the account when it meets the required reserve; if the transfer fails, the recipient receives a recoverable credit. The upgrades are recorded separately in the deployment manifest.

Namespace claim and objection windows, the 5,000 XLM fee and refund entitlements remain unchanged. See [governance and upgrades](/concepts/governance#allocator-upgrade-flow).

| Service | Address |
| --- | --- |
| Soran console | [soran.domains](https://soran.domains) |

| SDK demonstration app | [Open Soran Studio](https://soran-studio.throbbing-cloud-0f8e.workers.dev/) |

These services use the current deployment. Hosted MCP runs version **0.8.0**; signing tools are [local-only](/agents/access#native-usernames-in-local-mode). Billing and marketplace features are disabled on this setup. Check [service status](/api/status) when integrating.

The 8 September console/API update checks [current namespace ownership](/platform/console#current-ownership-checks), preserves the transaction hash after an [interrupted submission](/api/overview#submission-responses), and lets you recover an interrupted renewal before attempting another. The console also checks a maximum network fee and a short transaction expiry before wallet approval. Its name-management page supports full muxed identities through Universal Lookup.

The following changes are implemented in the next source revision. They have **not been published or deployed**. The package versions, hosted services and contract addresses listed above remain the release reference.
