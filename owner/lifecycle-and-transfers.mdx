title: "Lifecycle and transfers"
description: "Owner operations, separate namespace transfers and the irreversible permanence lock."
---

Use the [configured Owner SDK](/owner/issuing-from-code) for namespace-authorized lifecycle operations. The contracts enforce policy and signing authority.

## Reclaim, renew and treasury

```ts
await owner.reclaim("acme", "alice");
await owner.renew("acme", "alice", 86_400);
await owner.setTreasury("acme", treasuryAddress);
```

Reclaim requires reclaimability. Renewal extends an eligible finite term; zero-term names cannot be renewed as if they had a finite expiry. Treasury config controls custody for future reclaims. A current name expires only when ledger time is strictly greater than its finite expiry.

## Transfer the namespace

```ts
await owner.proposeNamespaceTransfer("acme", newOwnerAddress);
const pending = await owner.pendingNamespaceTransfer("acme");
await owner.cancelNamespaceTransfer("acme");
```

The recipient uses its own configured `SoranOwner` client to call `acceptNamespaceTransfer("acme")`. Ownership moves on acceptance, not proposal. This Registry transfer is distinct from an individual name's Registrar transfer in the Holder SDK or console Names view.

## Change routing

```ts
await owner.setResolver("acme", resolverAddress);
```

On an unlocked namespace the owner can change eligible routing. A different Resolver has different storage; existing address, memo, text and reverse records do not migrate automatically. A strict native payment lookup cannot assume a cleared or incompatible Resolver means a safe built-in memo-free destination. Plan and verify migration before repointing.

A permanent Registry Resolver pointer cannot change. Holder records within that fixed Resolver remain mutable.

## Make the namespace permanent

```ts
await owner.makePermanent("acme", { confirmIrreversible: true });
```

This is an irreversible [contract transition](/concepts/ownership-guarantees), subject to zero-term policy, clean provenance and current wiring checks. It freezes eligible namespace code and routing and disables reclaim. It does not freeze holder-controlled payment records or Universal Lookup governance.

Read `policy`, `isPermanent`, and `nameState` before making lifecycle decisions. A non-reclaimable zero-term policy remains **unlocked** until the required permanence transition has completed.

## Storage availability

Archived contract state still belongs to its recorded owner. Write flows can require extra signed restoration transactions and their network fees. Reads must report unavailable/archived state honestly; a read-only simulation does not guarantee a restore happened. Check included transaction hashes before retrying an uncertain operation.
