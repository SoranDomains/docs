---
title: "Issuing from code"
description: "Use the Owner SDK to issue names through the namespace Registrar with owner authorization."
---

The Owner SDK writes to Registry and the namespace's Registrar/Resolver. It does not route writes through Universal Lookup. Read integrations use the [Lookup SDK](/sdk/installation).

These examples target Owner **0.7.0** with Stellar SDK 17. See [release status](/reference/release-status) for verified package versions and the matching testnet contracts. You can also use the app for namespace operations.

For app signup and user-authorized registration, use [automatic username claiming](/owner/automatic-claiming). The owner configures on-chain fees, receiving wallets and reservations once; each user authorizes their own claim. The ordinary owner issuance methods below require Manual mode. Public mode blocks them even while public claims are paused.

```ts
import { SoranOwner } from "@sorandomains/owner";
const owner = new SoranOwner({
  signer: walletSigner,
  registryId: deployment.registryId,
  rpcUrl: deployment.rpcUrl,
  passphrase: deployment.passphrase,
});
```

`walletSigner` implements `publicKey()` and `signTransaction(xdr, options)` using a classic G transaction-source account. `keypairSigner` is available for securely configured backend scripts. Contract C ownership or recipient support does not imply arbitrary contract-wallet signing through this adapter; contract authorization needs a compatible integration. The SDK discovers the namespace Registrar from Registry.

## Issue one or a batch

```ts
await owner.issue("acme", "alice", aliceAddress);

const batch = await owner.issueBatch("acme", [
  { label: "alice", holder: aliceAddress },
  { label: "bob", holder: bobAddress },
]);
for (const outcome of batch.outcomes) {
  if (!outcome.issued) console.warn(outcome.label, outcome.reason);
}
```

A batch contains at most 23 names. The resulting name's initial built-in address is its holder; a native Resolver is needed for the strict memo-aware integration. Future holder instructions can override that address. Issuance applies the namespace policy and generation rules.

Manual issuance does not charge the public username claim price. In Public mode, use the native user claim method so the configured fee, eligibility, reservation and quota rules apply. Reserved assignment is the explicit owner-authorized exception. The top-level namespace escrow and Stellar transaction/storage fees remain separate.

## Check batch outcomes

The SDK prefers confirmed transaction events (`outcomeSource: "events"`) for per-label issuance outcomes. If transaction metadata is unusable, it can report an informational state reread (`outcomeSource: "reread"`). Re-read classifications can be affected by concurrent state changes; inspect the source of the result.

The contract skips already-held labels in a batch. Still check uncertain transaction hashes before retrying: expired/reissued state and other intervening activity can change the result of a later transaction.

## Authorization

Namespace issuance requires the on-chain owner. A hosted console admin/issuer role does not create new contract signing authority. Owner power also does not confer a holder's record-update or transfer authority.

Names must be ASCII before SDK lowercase normalization. Malformed labels and Unicode lookalikes are rejected. Simulation detects many contract rejections before signing; `OwnerError` exposes code/name and can carry `txHash` after submission.
