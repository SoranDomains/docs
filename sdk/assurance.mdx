---
title: "Resolver assurance"
description: "Understand precisely what locked, attested and untainted Resolver provenance proves."
---

`assurance(name)` describes a namespace's Resolver provenance. It does not certify that a payment is safe or that its destination cannot change.

```ts
const assurance = await soran.assurance("alice.nova");
// { resolverAttested, resolverTainted, resolverLocked, trustworthy }
```

| Field | Meaning |
| --- | --- |
| `resolverAttested` | Current Resolver pointer matches Registry's attested deployment |
| `resolverTainted` | Registry records that the attested Resolver has upgraded |
| `resolverLocked` | Current pointer has been permanently locked |
| `trustworthy` | Locked, attested and untainted |

Universal mode obtains these facts through Lookup's namespace metadata. Direct compatibility mode reads their Registry equivalents.

## Limits of the result

Holders may change their address, memo and text even when `trustworthy` is true. A recipient account can belong to an exchange or another party. The result does not establish that a name holder owns the destination account or that a memo identifies a particular person.

It also does not attest Universal Lookup's current executable code or governance. Lookup can be upgraded with no mandatory delay, and your RPC remains a trusted input. Use [namespace metadata](/concepts/ownership-guarantees) for the broader permanence predicate; do not infer all ownership guarantees from this narrower result.

For a payment, assess these boundaries, inspect the complete instruction and call `verifyPayment` near confirmation. Never replace a required memo with an address-only convenience read because provenance is locked.
