Identity views combine on-chain metadata with optional indexed discovery. Keep their sources visible.

## Holdings pages

```ts
const page = await soran.namesOfPage(address, { limit: 40 });
console.log(page.names);
console.log(page.coverage, page.verification);
if (page.hasMore) {
  const next = await soran.namesOfPage(address, { cursor: page.nextCursor!, limit: 40 });
}
```

`hintUrl` supplies candidate names. The SDK verifies each candidate's current holder and activity through Universal Lookup in universal mode. Each page checks at most 100 candidates with bounded concurrency. A failed check is counted separately from a proven stale or nonheld candidate.

| Field | Meaning |
| --- | --- |
| `nextCursor`, `hasMore` | How to continue candidate discovery |
| `verification` | Counts of candidates, verified names, exclusions and failed checks |
| `coverage` | Indexer's processed/head ledgers and known gaps, or `null` |
| `complete` | Final page, indexer reports complete coverage, and no candidate verification failures |

Coverage is the indexer's report, not proof against omission. `namesOf(address)` is a compatibility aggregate of up to 1,000 candidates and throws `INCOMPLETE` for partial results. `walletProfile.names` is its first verified page; continue using `walletProfile.holdings` instead of assuming it contains every name.

## Profiles

`profile(name)` reads these standard text keys through Lookup:

```ts
import { PROFILE_KEYS } from "@sorandomains/lookup";
// org, url, email, description, avatar, location, twitter, github
const profile = await soran.profile("alice.nova");
```

Values are current-generation holder-authored text, not verified real-world claims. Escape them and validate URL schemes before linking. Arbitrary text uses `text(name,key)`; keys are not globally enumerable. Lookup keys are nonempty Soroban Symbols up to 32 bytes and returned text is bounded to 4,096 UTF-8 bytes. Oversized historical text errors rather than being truncated.

## Aggregates and history

`identity(name)` combines details, profile and optional display-name enrichments. Details and profile fail closed; the holder/recipient/namespace-owner display-name enrichments can degrade to `null`. `walletProfile(address)` combines Primary, scoped reverse candidates, a holdings page and profile.

These aggregates perform several reads. They are not one atomic ledger snapshot. `details` checks for inconsistent generation/routing across its reads, but application code must still treat results as point-in-time data.

`history(name)` is a bounded indexed timeline with transaction and ledger references. Contract state has expiry timestamps, but it does not store a complete registration history. Chain-event timestamps are distinct from indexer ingestion time, and legacy issuance metadata can be unknown. Use the HTTP [history and events cursors](/api/events) for durable pagination rather than assuming a bounded SDK history result is exhaustive.
