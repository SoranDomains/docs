Install **Lookup 0.8.0** to read names, payment instructions and identity records. It needs no signer. The testnet preset uses the current [Registry, Lookup and Primary deployment](/reference/release-status).

```bash
npm install @sorandomains/lookup@0.8.0 @stellar/stellar-sdk@^17
```

The supported Stellar SDK peer range is `>=17 <18`. The package is ESM with TypeScript types and supports Node, browsers and workers.

To write records, use the [Holder SDK](/holder/managing-your-name). To issue names or configure a namespace, use the [Owner SDK](/owner/issuing-from-code). Their `TxSigner` adapters use a classic G account as the transaction source. Contract-wallet authorization requires a compatible integration of its own.

## Universal mode is the default

```ts
import { Soran } from "@sorandomains/lookup";

const soran = new Soran({
  network: "testnet",
  reverseNamespaces: ["nova"],
  hintUrl: "https://api.soran.domains",
  timeoutMs: 10_000,
});
```

This example uses the bundled testnet configuration. Universal Lookup discovers each namespace's Registrar and Resolver on chain.

For a custom deployment, provide its matching `registryId`, `lookupId`, `rpcUrl` and `passphrase`. The [quickstart](/quickstart#configure-one-shared-reader) shows explicit current testnet IDs. Pinning those values lets you select a deployment independently of package updates.

- A missing Lookup configuration throws `CONFIG`.
- A custom Registry or network passphrase does not inherit an unrelated Lookup or Primary pin.
- The SDK currently provides a testnet preset only.

### Configure Primary reads

In universal mode, `primaryId` has three meanings:

| Value | G/C Primary behavior |
| --- | --- |
| Explicit contract ID | Must match `Lookup.primary()`. |
| Omitted for a custom deployment | Use Lookup's configured Primary anchor. |
| `null` | Disable G/C Primary reads. |

Complete-M Primary is stored in Lookup and does not use this Primary pin.

## Explicit direct compatibility mode

```ts
import { Soran } from "@sorandomains/lookup";

// Supply a reviewed deployment; these are your application's configuration.
declare const deployment: {
  registryId: string;
  primaryId: string;
  rpcUrl: string;
  passphrase: string;
};

const direct = new Soran({
  registryId: deployment.registryId,
  rpcUrl: deployment.rpcUrl,
  passphrase: deployment.passphrase,
  resolutionMode: "direct",
  primaryId: deployment.primaryId,
});
```

Choose direct mode only for an integration that deliberately reads native Resolvers itself. `lookupId: null` also selects it.

Direct mode checks Registry, Registrar authority and payment capability. Version 1 selects the native payment ABI; version 2 additionally requires destination version 2 and supports M. Failed or unknown capability reads throw instead of selecting an older ABI.

`lookup`, `namespaceMetadata`, `nameMetadata` and M identity reads require universal mode.

## Other options

| Option | Purpose |
| --- | --- |
| `reverseNamespaces` | Ordered namespace candidates for reverse probing; default empty |
| `hintUrl` | Optional indexed discovery for namespace candidates, holdings and history |
| `resolverCacheTtlMs` | Direct-mode routing cache lifetime; default 30,000 ms, `0` disables it |
| `timeoutMs` | Per-chain-read wait bound; a larger aggregate can take longer; does not cancel the underlying request |

HTTPS is required except for allowed local-development hosts. Names are checked for ASCII before lowercasing, and whitespace is not trimmed. Malformed configuration or name input must be corrected rather than retried as an absent record.

See [reference](/sdk/reference) for methods, result types and typed failures.
