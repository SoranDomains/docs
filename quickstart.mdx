## Configure one shared reader

Install Lookup with Stellar SDK 17:

```bash
npm install @sorandomains/lookup@0.5.0 @stellar/stellar-sdk@^17
```

The package's testnet preset includes the verified Registry, Lookup and Primary addresses:

```ts
import { Soran } from "@sorandomains/lookup";

const soran = new Soran({
  network: "testnet",
  reverseNamespaces: ["nova"],
});
```

Universal mode is the default. Its contract validates current namespace routing on chain. Missing Lookup configuration throws `CONFIG`; it does not silently read a Resolver directly.

## Read the whole payment instruction

```ts
const payment = await soran.resolvePayment("Alice.Nova");
// payment = { address: "G... or C...", memo: { type: "none" } }
// or memo: { type: "id", value: "123456" }, text, or hash

if (!(await soran.verifyPayment("alice.nova", payment))) {
  throw new Error("Payment instructions changed; review them again");
}
```

Preserve **both** fields when constructing the payment. No memo is needed for `memo.type === "none"`. For a required memo, include its exact type and value or refuse the payment. IDs are decimal strings; never convert them to JavaScript numbers.

A `G...` address can use a classic Stellar payment. A `C...` address requires an appropriate contract/token transfer flow and supports only memo `none` in this ABI. Also honor the recipient account's memo-required setting. A transaction has only one classic memo: split payments needing different memos.

Direct muxed `M...` addresses are not currently supported by Soran's payment interface. They must not be stripped to a G address or automatically converted to a memo. See [supported addresses and complete examples](/concepts/payment-destinations) for G, G plus memo, C and the M-address limitation.

A successful read is a point-in-time answer. Rechecking catches stale client data; it cannot prevent a later record change before a separate payment settles.

## Read ownership and display names separately

```ts
const name = await soran.nameMetadata("alice.nova");
const namespace = await soran.namespaceMetadata("nova");
const displayName = await soran.primaryOf(senderAddress);
```

`name.holder` and `name.builtinAddress` are ownership metadata, not necessarily the effective payment address. Use the complete payment result for payments. Primary and reverse names identify an account, not a customer memo on a pooled exchange account.

Use [namespace assurance](/sdk/assurance) to assess Resolver provenance. It does not freeze holder records or remove Lookup governance and RPC trust.
