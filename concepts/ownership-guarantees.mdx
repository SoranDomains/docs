---
title: "Ownership guarantees"
description: "Distinguish no expiry, reclaimability, permanence and mutable payment records."
---

A namespace's on-chain policy describes reclaimability, transfers, trading and default term. Read both policy and provenance before displaying an ownership guarantee.

| State | Meaning |
| --- | --- |
| Reclaimable | The namespace owner can reclaim names under the contract policy |
| Finite-term | A name expires when ledger time is strictly greater than its nonzero `expires_at` |
| No expiry | `expires_at == 0`; this alone does not freeze code or routing |
| Permanent | The namespace completed the Registry-verified permanence lock with eligible Registrar and Resolver provenance |

These properties are not always mutually exclusive before permanence: for example, a reclaimable namespace can issue names without an expiry date. Do not turn `expires_at == 0` into a permanent badge.

## `make_permanent`: the one-way door

An eligible namespace owner can irreversibly make the namespace permanent. The contract transition disables reclaimability, freezes the relevant Registrar/Resolver implementation paths and locks the Registry's Resolver pointer atomically. A failed eligibility check leaves the state unchanged.

Eligibility depends on the Registry's originally pinned code and deployment attestations, neither contract having been tainted by an upgrade, correct current wiring, and a zero default term. A finite-term policy is not made permanent by hiding its expiry. Restoring an original Wasm after an upgrade does not erase taint.

Before the lock, eligible owner-governed contracts can still be upgraded. A policy advertised by changeable code is not the same guarantee as a completed permanent lock.

## Verify the full namespace state

```ts
const namespace = await soran.namespaceMetadata("nova");
if (namespace?.permanent) {
  // The Lookup checked current lock, attestation, authority, taints and policy.
}
const name = await soran.nameMetadata("alice.nova");
// Inspect name?.active, name?.noExpiry and name?.namespacePermanent separately.
```

The narrower [`assurance()`](/sdk/assurance) result concerns Resolver provenance. It does not certify every part of ownership or the Universal Lookup implementation itself.

## What permanence does not freeze

Holders can still update their own addresses, memos and profile records. Permitted holder transfers remain possible. A permanent Resolver's code and pointer being fixed does not make its answers immutable.

Storage TTL still requires upkeep or restoration. Universal Lookup remains governed independently and can be upgraded without a mandatory delay. Integrators must assess that [governance boundary](/concepts/governance), the current code and the RPC they use.
