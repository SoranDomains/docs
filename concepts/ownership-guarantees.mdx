---
title: "Ownership guarantees"
description: "Understand what a holder owns and what a permanent namespace protects."
---

A name's ownership rules come from its namespace. Before accepting a name, check whether the owner can reclaim it, whether it expires and whether the namespace has completed its permanent lock.

| State | Meaning |
| --- | --- |
| Reclaimable | The namespace owner can reclaim names under the contract policy |
| Finite-term | A name expires when ledger time is strictly greater than its nonzero `expires_at` |
| No expiry | `expires_at == 0`; there is no ownership deadline |
| Permanent | Registry verified and locked the namespace's eligible Registrar and Resolver, preventing owner reclaim and later code or routing changes |

These properties can overlap. A reclaimable name can have no expiry date, for example. **No expiry does not mean permanent:** the owner may still have reclaim or upgrade powers.

## `make_permanent`: the one-way door

An eligible namespace owner calls `make_permanent` to give up those powers irreversibly. The transaction disables reclaimability, freezes the Registrar and Resolver code, and locks Registry's Resolver pointer together. If an eligibility check fails, none of these changes takes effect.

Registry checks that both contracts were deployed from its pinned code, remain correctly connected and have never been upgraded. The Registrar must also have a zero default term. A finite-term namespace cannot pass this transition, and restoring original code after an upgrade does not restore eligibility.

Until this lock succeeds, eligible contracts remain under owner upgrade control.

## Verify the full namespace state

```ts
const namespace = await soran.namespaceMetadata("nova");
if (namespace?.permanent) {
  // The Lookup checked current lock, attestation, authority, taints and policy.
}
const name = await soran.nameMetadata("alice.nova");
// Inspect name?.active, name?.noExpiry and name?.namespacePermanent separately.
```

Use namespace and name metadata to display ownership status. [`assurance()`](/sdk/assurance) has a narrower purpose: it checks Resolver provenance, not the full ownership guarantee or Lookup's own code.

## What permanence does not freeze

Holders can still update their payment addresses, memos and profiles. They can also transfer names where the policy permits. Permanence fixes the rules and routing; it does not freeze holder-controlled records.

Storage still needs upkeep or restoration. Universal Lookup has its own [governance rules](/concepts/governance) and can be upgraded without a mandatory delay, even for reads of permanent namespaces.
